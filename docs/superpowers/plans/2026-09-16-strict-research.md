# Strict research implementation plan

Goal: qualify substantially fewer, evidence-backed candidates without deleting opinions or public insider records.

Architecture: one pure qualification policy over existing typed capture, optional versioned receipt on Result and saved checks, explicit scan policy and versioned ranking. Existing provider, model, comparison and native UI components are reused.

1. Implement qualification measurements, source/citation binding and exclusion reasons in StockSageResearchQualification.swift; cover both horizons and missing/stale/boundary inputs.
2. Bind production capture, mandatory screen fact, original model result and strict shortlist in HorizonResearch/Ranking. Generic legacy research remains explicitly unqualified-policy nil; no archive reclassification.
3. Extend ResearchHistory optional receipt fields and validate full pool/count/amendment identity while preserving legacy encoding and review dates.
4. Show qualified counts and exclusion reasons in existing Mac/iPhone research views; preserve raw opinions and original evidence.
5. Execute focused native checks and full canonical Mac then iPhone gates, review source hashes, commit/merge/push, build signed Release and install with owner-data backup.
6. Run fresh server research within the approved paid window, retain all outcomes/receipts, and stop the pod by the approved deadline. A paid-time extension requires separate authorization.
