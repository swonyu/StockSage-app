**Risks / constraint conflicts:**

BLOCKING-RISK CANDIDATES.
1) Endpoint privacy is an existing, tested invariant. StockSageLocalModelServer.swift:749-750 states the endpoint and request headers are never copied into the diagnostic payload, and StockSageTests/StockSageLocalModelServerTests.swift:178 asserts the encoded events contain no "127.0.0.1" and no "/v1/chat/completions". 'Endpoint profile' must therefore be a closed enum LABEL, never a URL, host or port. Writing the URL into a receipt would break that test and leak a network address into an owner-readable file.
2) Pinning must not become changing. `PromptVersion.current` is explicitly frozen — StockSageAIAssessment.swift:486-492 'Version 1 was frozen on 2026-09-15 against the benchmark ... is not adopted until a measured corpus says it is at least as good.' Adding `top_p` or `seed` to `chatRequest` (StockSageLocalModelServer.swift:653-696) changes the request body and therefore the model's output distribution against that frozen benchmark. Task 5 as written only requires RECORDING settings; introducing new sampling parameters is a separate, measured change and must be versioned.
3) Do not claim determinism that was not measured. The same file already carries a hard warning against porting unverified model claims (StockSageLocalModelServer.swift:216-236: the tokenizer bound 'is UNVERIFIED for google/gemma-4-31b-qat as a general claim' and the LM Studio build 'exposes no tokenizer endpoint'). Seed support on the shipped LM Studio/RunPod endpoints has not been measured in this tree. Record `seed: nil` meaning 'not requested', and never let a recorded seed imply reproducibility the plan's own replay test has not demonstrated.
4) Legacy-bytes constraint. `CompletedCheck`/`Prediction` are re-encoded and size-capped on every save (StockSageResearchHistory.swift:1074 `bytes.count <= maximumCompletedChecksBytes`, :950 = 16 MiB) and re-validated on load (:1068 `validChecks`). Every new field must be `var x: T? = nil` so Swift's synthesized `encodeIfPresent` omits it for legacy archives — follow the existing precedent comments at :997-1000 ('Absent on every archive written before this existed; decodes as empty, never guessed'). A non-optional field would invalidate every saved receipt.
5) A cohort rule must never hide evidence. 'Differing model/config hashes must never be compared as one quality cohort' has to be implemented as SEPARATE REPORTING, not as filtering: dropping a receipt from a view because its config differs would violate the global 'preserve every supplied evidence record' constraint and the 'missing data stays visibly uncertain' constraint. A receipt with `inferenceProfile == nil` (every legacy receipt) must stay fully readable and be labelled 'configuration unrecorded', never treated as a mismatch or as negative evidence.
6) Second-model-call ambiguity against 'one controlled retry only'. Beyond the transport-level retry, `StockSageAIAssessment.complete` makes a SECOND model call with DIFFERENT bytes — StockSageAIAssessment.swift:576-584 (`let repair = evidenceRepairPrompt(draft.text, facts: facts)` then `generate(repair, phase: "evidence-repair")`), mirrored in `StockSageAIAssessments.performAssessment` at :1003-1020. Each of those calls carries its own internal `for attempt in 0...1` truncation retry, so one research turn can legitimately produce up to four POSTs. This is existing, intentional, format-only repair guarded by `preservesOpinion` (:583, :786-790), but the receipt should name it (phase + retryReason) so 'one controlled retry' is auditable rather than contradicted.
